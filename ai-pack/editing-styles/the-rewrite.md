# The Rewrite

A document exists but it's fundamentally misaligned. It's trying to say something, but it's missing the mark. Patching it won't work — the foundation is wrong. The rewrite is for when you need to step back, figure out what the document should actually be, and write it fresh.

## When to Use

- A doc covers the wrong thing — it explains feature X when what's needed is feature Y
- A doc contradicts itself — one section says one thing, another says the opposite
- A doc was written for an old version of the system and the system has moved on
- A doc tries to do too many things at once and does none of them well

## How It Works

### 1. Diagnose What Went Wrong

Read the existing doc. What was it trying to say? Where does it fail? Is the goal wrong, the approach wrong, or both?

### 2. Decide What Should Be There Instead

The new goal might contradict the old one. That's fine. The system evolved. The doc needs to match reality, not legacy intent.

### 3. Pick a Knowledge Theory

Go to [knowledge-theories](../knowledge-theories/) and choose the framework that fits:

- **The Why Layer** — if the doc needs to connect technical decisions to business value
- **The How Layer** — if the doc needs comprehensive technical explanation
- **The What Layer** — if the doc needs to map where things live and who owns them

### 4. Pick a Writing Style

Go to [writing-styles](../writing-styles/) and choose the voice and structure:

- **Use-Case-Driven** — if the doc should start with a human goal and drill down to technical details

### 5. Write It

Start from a blank file. Don't carry forward paragraphs from the old doc. If a sentence from the old doc survives, it earned its place — it wasn't inherited.

### 6. Replace

Delete the old doc. Drop in the new one. If the old doc was a grab-bag of multiple topics, it might become two or three focused docs. That's correct — one topic per doc.

## The Discipline

The hardest part is letting go of the old text. You wrote it (or someone did). It has effort in it. But a doc that misleads is worse than no doc at all. The rewrite is not laziness — it's honesty.

## When Not to Use

- A small factual error — use [The Touch-Up](./the-touch-up.md) instead
- A doc that's structurally sound but reads flat — needs surface polish, not a rewrite
- A doc that's too long but says the right things — needs cutting, not rewriting

The rewrite is for when the doc's foundation is wrong, not when it needs trimming.
