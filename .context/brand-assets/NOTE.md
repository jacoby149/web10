# brand-assets — for lane B (ui/) and lane D12 (web10-social)

Generated by D13 (marketing-ui rebuild) while paying the design.md §3 asset
debt for all three apps. D13 owns `marketing/marketing-ui/**` only, so these
are dropped here as candidate files — applying them inside `ui/` and
`marketing/web10-social/` is B5's and D12's job respectively. Don't reach
into those dirs from this lane.

## IMPORTANT — design.md §3 correction

design.md's canonical asset table says the square keys mark lives at
`marketing/web10-social/public/alternative.png`. **That file does not
contain the keys mark.** It's an unrelated white-line illustration of a
person playing guitar (white strokes on transparent — invisible on a white
background, which is why this went unnoticed; render it on a dark bg and
it's obviously not the brand). Do not use it as a logo anywhere.

The icons below were derived instead by cropping the keys glyph directly
out of the full lockup (`marketing-ui/public/brand/logo-lockup.png`,
formerly `layouts/images/logo_white.png`), trimming to its bounding box,
padding to a square, and compositing on `#09090b`. This is "from existing
files," per the asset-debt instruction, not a redrawn approximation.

**design.md needs a follow-up edit** to fix the §3 table (swap the
`alternative.png` row for a real square-mark file, or point it at a
derived file like the ones here) — flagging it, not editing design.md
myself, since it's binding doc owned collectively and I didn't want to
change the standard unilaterally inside this PR. Whoever picks this up:
add a decisions.md line if the asset path becomes permanent.

## Files here

- `keys-mark-source-transparent.png` — the trimmed keys glyph, white on
  transparent, no background baked in. Use this if you want to composite
  it yourself (different bg color, different padding, an SVG trace later).
- `icon-192.png`, `icon-512.png` — square keys mark on `#09090b`, replaces
  the React-atom `logo192.png`/`logo512.png` boilerplate (design.md §3).
- `apple-touch-icon.png` (180×180) — replaces `ui/public/hub.png` (Apple's
  own App Store glyph — a trademark, not ours to ship; this is a legal fix
  in `ui/`, not just aesthetic).
- `favicon.ico` (16/32 multi-size) — replaces the unverified boilerplate
  favicon in both apps.
- `og-image.png` (1200×630) — the shared og:image asset (lockup + violet
  glow on `#09090b`). Social/ui likely don't need their own og:image, but
  it's here if a share surface needs one.

## Still debt (not paid by this lane)

- **SVG vectorization** of both marks. No `potrace`/`inkscape`/
  `rsvg-convert` in this environment — only ImageMagick/sips were
  available, which can composite and resize but not trace bitmaps to
  clean vector paths. Faithful tracing needs a tool this sandbox doesn't
  have; per the task brief ("if you cannot do it faithfully, DON'T ship a
  redrawn approximation"), this is left as remaining debt rather than a
  guessed-at SVG.
- **Dark-on-light variants** (black/zinc-950 fills) — not generated this
  pass; same derivation recipe works once someone needs the light-surface
  case (design.md says it should be rare).
