# September 2026 Improvement Ledger

This is a plain record of what changed for people building, running and using web10 during September, including the repairs needed to make earlier work useful. It is not a scorecard of AI productivity or evidence that AI caused these improvements.

Dates below are the dates printed in the changelog, not commit or merge dates. PR numbers were matched to subjects in `git log --all --since=2026-09-01 --until=2026-10-03 --format='%ad || %h || %s' --date=short`; `not recorded` means no sufficiently clear PR match was established in that history. A PR may therefore have merged after its ledger date. Source links name the changelog version; where versions repeat, the label also names the entry.

`fix` means a repair to existing behavior. `feature` means a useful new capability or recorded body of knowledge, including high-impact social UI. `evolutionary` means a substantial evolution of a backend or shared mechanism within the existing system, not merely any backend addition or shared component. `revolutionary` is reserved for a fundamental remake of the whole backend, system or human-computer interaction model, leaving that model almost unrecognizable. Scope and mechanism, not impact or PR size alone, decide the tier. `Changed` names only the evidenced subset of KB, code and tests for that row's improvement, not everything in its PR. KB means substantive knowledge or intent documentation, including public guides and recorded design decisions; routine changelog entries, plan/lane ticks and checkbox-only spec updates do not qualify. Tests means relevant test code or fixtures were added, edited or removed, not merely that an existing suite ran; screenshots alone do not qualify. A test removal is a changed artifact, not added assurance. Independent improvements within one entry are separated when they do different useful jobs; duplicate entries, merge housekeeping, routine dependency churn and pure lane planning are not counted.

All 287 rows were reviewed against the four tiers. These are two deliveries of that composition-model remake, not two independent whole-system revolutions. Retiring the feed endpoint through that existing engine (SEP-125), extracting social previews (SEP-113) and extracting monetization (SEP-128) substantially evolve the generic platform without remaking it again, so they are evolutionary.

Seven former feature rows are evolutionary on their recorded mechanisms: contact-anchored authentication unifies account entry, creation and recovery (SEP-009); node-owned imports replace the legacy pipeline with durable, restartable, idempotent jobs (SEP-037); a second access-controlled query boundary exposes group metadata without exposing raw tables (SEP-168); membership visibility becomes a group-level policy with public by-user reads (SEP-196); consensual contract reconciliation evolves shared SDK/authenticator contract maintenance (SEP-224); generic node bans extend filtering across read paths (SEP-225); and persistent node telemetry replaces volatile marketing memory (SEP-228). Smaller backend additions such as request budgets, tag filtering and SDK options remain features, as do high-impact social experiences such as Shorts, watch pages, group chat and rich-text composition. Existing repairs remain fixes even when their implementation changes substantially; knowledge-only designs remain features rather than claims of delivered backend evolution.
