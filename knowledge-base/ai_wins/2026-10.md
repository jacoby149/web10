# October 2026

Concrete changes recorded in the October changelog, in ascending date order.
Dates are from the changelog, not PR merge dates; order within a day is only a
reading order, not a claim about the time work finished.

PRs were checked against `git log --all --since=2026-10-01 --until=2026-10-30 --format='%ad || %h || %s' --date=short`.
`not recorded` means no matching implementation PR was verified in that history,
not that the work never merged; `local` additionally identifies an unmerged
record where that status is documented. A promotion PR is not substituted for a
missing implementation PR. Later verified PRs take precedence over older local
status notes, including #1291 and #1293.

`Changed` lists only evidenced changes for that row, not deployment status.
KB means substantive knowledge or intent documentation, including research,
operational guidance and security receipts; changelog entries and plan or lane
ticks do not count. Code includes build scripts and test harness tooling.
Tests means test files or assertions changed, not merely that tests were run.
Labels were checked against commit file lists and relevant documentation diffs;
unrelated changes elsewhere in a combined PR do not qualify a row.
`fix` marks a repair to existing behavior or documentation. `feature` marks a
new capability or useful knowledge record, including high-impact social UI and
separate reusable product records. `evolutionary` marks substantial evolution of
a backend or shared mechanism, not merely a large or useful feature.
`revolutionary` is reserved for a fundamental remake of the whole system,
backend or human-computer interaction that leaves it almost unrecognizable.
None of these rows meets that threshold. These are editorial labels, not
measured productivity or AI-attribution scores.

Repeated changelog copies count once. Distinct outcomes in a combined entry can
have separate rows with the same source and PR. Historical steps remain visible
when later work replaced them; they are not extra independent architecture wins.
Scan and planning rows describe knowledge work only, not runtime repairs.
No row establishes deployment, a fresh test run, independent security approval,
or completion of the open security campaign. The AI-wins summaries themselves
are excluded.
