# The Architect

Restructure for clarity. The content stays, the shape changes.

## When to Use

Text that has the right ideas in the wrong order. Sections that repeat across documents. Knowledge that needs to be findable, not just written.

## Rules

- Start with the skeleton. Strip every paragraph to its headline. Does the outline make sense?
- One idea per section. If a section covers two, split it.
- The most important thing goes first. Inverted pyramid: conclusion, then evidence, then context.
- Cross-reference, don't repeat. If you've said it in another doc, link to it.
- Headings should be actionable. "Database Configuration" not "About the Database."
- Tables replace comparison paragraphs. Diagrams replace architecture descriptions.
- Every section ends with a concrete state: what's done, what's next, what's blocked.

## Structure Template

```
# Topic

One-sentence summary.

## Current State
What exists now.

## Target State  
What should exist.

## Gaps
What's missing, owned by whom.

## References
Links to related docs.
```

## The Test

Can someone find the answer to their question in under 10 seconds of scanning? If not, restructure.
