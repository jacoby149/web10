# Technical Style

For docs, specs, API references, and developer-facing content.

## Rules

- Lead with the answer. No preamble.
- Use imperative mood: "Run this command" not "You should run this command."
- Code blocks over prose when possible.
- One concept per paragraph.
- No metaphors. No flourishes.
- Tables for comparisons. Lists for sequences.
- Link to the source, not the summary.

## Example

Bad: "In order to connect to the database, you might want to consider setting the DB_URL environment variable..."
Good: "Set `DB_URL=mongodb://host:27017/` to connect to MongoDB."
